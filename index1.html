What is Laya?

Laya solves a very common problem — classifying text — in an unusually fast way. Here's the idea in plain English.

💡 The best analogy Imagine you have 50 bins labelled with different emotions. Two approaches:

Autoregressive (GPT-style): Write out a long essay about the text, then eventually say which bin it belongs to — one word at a time, slow.

Non-autoregressive (Laya): Glance at all 50 bins simultaneously, score each in one instant, hand you the winner. Like a reflex — no deliberation needed.

This is why Laya is described as a System 1 decision engine. In cognitive science, System 1Daniel Kahneman's framework: System 1 = fast, automatic, instinctive. System 2 = slow, deliberate, analytical. thinking is fast and instinctive, while System 2 is slow and deliberate. Laya is the ML equivalent for classification tasks — instant, parallel, no generation required.

Three task types

📋 Typed Choice

Pick exactly one label from a fixed set you provide. Example: classify this tweet as "positive", "negative", or "neutral".

📊 Score (0–1)

Return a continuous confidence for a statement about the text. Example: how toxic is this comment? Returns 0.0–1.0.

✅ Yes / No

Binary classification: does this text match a condition? Example: is this question about billing? Yes or No.

At the ML level, Laya is a non-autoregressiveThe model computes all output positions simultaneously, rather than conditioning each token on the previous one. classification model built on a pre-trained language encoder.

The key insight: for classification, you don't need to generate text. You only need to score candidates. Laya exploits this to eliminate the autoregressive bottleneck entirely.

Laya includes a routerA lightweight dispatcher that inspects each incoming request and selects the appropriate model checkpoint to handle it. — a component that automatically selects the right model checkpointA saved set of model weights trained for a specific task type or domain. for each request.

✅ Why this matters Different classification tasks may benefit from different fine-tuned checkpoints. Instead of forcing the caller to know which model to use, the router dispatches automatically — so the same API entry point handles choice, score, and yes/no tasks without extra configuration. ⚠️ Verify router behavior from README

This design means you can add new checkpoint specializations without changing the API surface, and the router can balance load across checkpoints if needed.

How it Works

A step-by-step walkthrough of a single request, from your code to a classification result.

  1. Send your text and task type. You call the Laya API with your input text and specify the task: typed choice (fixed labels), score (0–1), or yes/no.
  2. The router selects a checkpoint. Laya's router inspects the request and picks the most appropriate checkpointA saved set of model weights fine-tuned for a specific task or domain. for the task. No manual model selection needed. ⚠️ Verify
  3. The encoder runs one forward pass. Your text is tokenized and fed through the neural network encoder. This happens exactly once — no loops, no generation steps.
  4. All labels are scored simultaneously. The encoder's final representation is compared against all candidate labels in parallel, producing a confidence score for each.
  5. You get the winner (and its score). The highest-confidence label is returned, along with its score. For yes/no tasks, the answer is simply the label with >50% confidence.

Code example

The API below is illustrative — verify the actual interface from the repo README.

ILLUSTRATIVE · Python
# Install: pip install laya  (⚠️VERIFY package name from repo)
from laya import Laya

client = Laya()

# --- Typed Choice ---
result = client.choice(
    text="This product is absolutely amazing!",
    labels=["positive", "negative", "neutral"]
)
print(result)
# {"label": "positive", "score": 0.94, "latency_ms": ~20}  ← ILLUSTRATIVE

# --- Score (0-1) ---
toxicity = client.score(
    text="Go away and never come back!",
    statement="This text is toxic"
)
print(toxicity)
# {"score": 0.81}  ← ILLUSTRATIVE

# --- Yes/No ---
is_billing = client.yes_no(
    text="When will my invoice arrive?",
    question="Is this a billing question?"
)
print(is_billing)
# {"answer": "yes", "confidence": 0.97}  ← ILLUSTRATIVE

Tips & Tricks

Practical advice for using Laya and laya-ultrafast in real projects.

💡 Tips

📋

TIP-1 · Use typed choice for fixed taxonomies

When your label set is stable and known in advance (sentiment categories, topic tags, intent classes), typed choice gives you the fastest, most deterministic results. Avoid using the score task as a workaround for multi-label classification.

📊

TIP-2 · Use score for nuanced decisions

When you need a gradient rather than a hard class — toxicity level, relevance degree, confidence of match — score (0–1) is more informative than yes/no and avoids arbitrary threshold decisions upstream.

🔀

TIP-3 · Let the router choose the checkpoint

Resist the urge to pin a specific checkpoint unless you have a strong reason. The router is designed to dispatch optimally. Manual checkpoint selection can break when new checkpoints are released. ⚠️ Verify

🚀

TIP-4 · Switch to laya-ultrafast at scale

If your workload exceeds ~100 requests per second, laya-ultrafast's batching can significantly improve GPU utilization. Start with base Laya for development and switch when you hit throughput ceilings. ⚠️ Verify QPS threshold from repo

🎯 Tricks

TRK-1 · Threshold score for soft yes/no

When to use it: you need a binary decision but want control over precision/recall tradeoff.
How: use score() and apply your own threshold (e.g., 0.6) rather than using yes_no() directly.
What it buys: tunable sensitivity without retraining.

TRK-2 · Cache repeated labels server-side

When to use it: you call Laya with the same fixed label set thousands of times per second.
How: pre-compute and cache the label embeddings on the server if the API supports it. ⚠️ Verify
What it buys: reduced encoder work per request.

TRK-3 · Shakedown at quick depth first

When to use it: integrating Laya into a new pipeline.
How: run 10 representative samples and check that outputs are sensible before scaling up.
What it buys: catches label-set mismatches and API misuse early.

Things to Avoid

Common mistakes that will give you poor results or unnecessary complexity.

⛔ AVD-1 · Using Laya for generative tasks

Symptom

You ask Laya to "summarize" or "explain" text and get back a label like "positive" — useless for your actual goal.

Cause

Laya is a classification engine, not a generative model. It can only output from a predefined label set, score, or yes/no.

Fix

Use a generative LLM (GPT-4, Claude, etc.) for tasks requiring generated text. Use Laya only when the output is a label, score, or boolean.

⛔ AVD-2 · Passing unbounded or dynamic label sets

Symptom

You pass thousands of dynamically generated labels and results become noisy or slow, contrary to expectations.

Cause

Laya's speed advantage assumes a reasonably fixed, known label space. Very large or ephemeral label sets can defeat the architecture's assumptions. ⚠️ Verify label-set size limits

Fix

Define a stable label taxonomy. If the label space is unbounded, reconsider whether classification is the right approach.

⛔ AVD-3 · Using base Laya when throughput is the bottleneck

Symptom

Under high concurrent load, your Laya service is the bottleneck, GPUs are underutilized, and latency spikes.

Cause

Base Laya handles requests individually. Without batching, GPU compute is wasted between requests.

Fix

Switch to laya-ultrafast for production high-QPS workloads. Its batching layer amortizes GPU cost across concurrent requests. ⚠️ Verify batching from repo

Frequently Asked Questions

Real questions a developer will ask after reading about these repos.

What does "non-autoregressive" mean in plain English?

Most large language models generate text one token (word piece) at a time, and each token depends on all the previous ones. This is called autoregressive — like reading aloud one word at a time. For classification, this is inefficient.

A non-autoregressive model produces all outputs simultaneously, in one step, without sequential dependencies. Think of it like reading the entire sentence at a glance and instantly knowing the answer, rather than sounding it out word by word. For classification tasks, this makes it dramatically faster.

How is Laya different from asking GPT-4 or Claude to classify text?

When you ask GPT-4 to classify something, it generates a text response token-by-token (often including reasoning text before the label) and you still have to parse the output. It's like hiring a novelist to answer a yes/no question — powerful but wasteful for that task.

Laya is purpose-built for classification: no generation, no parsing, structured output directly. It's typically much faster and cheaper for high-volume classification, but it cannot do anything generative (summaries, rewrites, explanations).

What languages does Laya support?

The repo description states "100+ languages." ⚠️ Verify The exact list and which languages are best supported likely depends on the underlying pre-trained encoder's multilingual training. Verify the exact language list from the repo README before relying on support for a specific language in production.

What is laya-ultrafast, and why does it exist?

laya-ultrafast exists to maximize throughput — the number of requests the system can handle per second — rather than minimizing per-request latency. Base Laya is already fast per request, but at scale, GPU utilization can be poor if requests are handled one at a time.

laya-ultrafast applies a batching/serving optimization pattern (the "jev-ultrafast" approach ⚠️ Verify) to Laya, grouping concurrent requests before each inference call so the GPU is fully utilized.

Start with base Laya: for development, experimentation, and workloads under ~50–100 requests per second. Simpler setup, easier to debug.

Glossary

Every ML and systems term used on this page, defined in plain English.

Non-autoregressive A model that produces all outputs simultaneously in one step, rather than generating one token at a time and conditioning each on the previous. Makes classification dramatically faster.
System 1 (ML usage) Borrowed from cognitive science (Kahneman): fast, instinctive processing. In Laya's context: a single-pass decision made without deliberate multi-step reasoning.
Forward pass One complete pass of data through a neural network from input to output, producing predictions. In non-autoregressive models, one forward pass is all that's needed.
Checkpoint A saved snapshot of a trained model's weights, typically fine-tuned for a specific task or domain. Loading a checkpoint makes the model ready to run that task.
Router In Laya: a lightweight component that inspects each incoming request and selects the appropriate checkpoint to handle it, without the caller specifying the model.
Typed choice A classification task where the model picks exactly one label from a caller-supplied fixed set. Example: classify into ["positive", "negative", "neutral"].
Score (0–1) A continuous confidence value indicating how strongly a statement applies to a piece of text. 0 = not at all, 1 = completely. More granular than a binary yes/no.
Throughput The number of requests a system can successfully process per unit of time (e.g., 500 req/s). High throughput is the primary goal of laya-ultrafast.
Latency The time elapsed between sending a single request and receiving its response. A system can have low latency (fast per request) but still have low throughput if it can't handle many simultaneous requests.
Batching Grouping multiple inference requests together and processing them in a single GPU call. Improves throughput by amortizing the fixed overhead of each GPU invocation across many requests.
